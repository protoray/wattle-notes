# Architecture

The React interface calls narrow Tauri commands. Rust owns local files, SQLite, encryption keys, credentials, and Drive operations. The renderer never receives the master key or Google refresh token. A recovery key is shown once to the user during setup.

## Local vault

The chosen folder is the file boundary. Notes are UTF-8 `.md` files. Attachments are ordinary files; imported ones use `attachments/`. `new_notes_id` identifies a note independently of its path. The `.notes/` directory contains the SQLite index/queue, write journal, local immutable revision snapshots, retained attachment blobs, encryption configuration, and temporary encrypted transfers. These internal files are not included in ordinary Markdown exports or mirrored to Drive.

The application was renamed from New Notes to Wattle Notes. The legacy `new_notes_id` frontmatter field, `org.newnotes.desktop` application/credential identifier, and `new-notes-theme` preference key remain stable for compatibility with existing vaults, saved credentials, and preferences. Existing app-managed Drive folders retain their names; newly created roots use `Wattle Notes - <vault name>`. Remote discovery uses stable object properties rather than the displayed folder name.

External files are scanned every three seconds while the UI is open. Note saves include an expected content hash. Conflicting external content and the editor draft become separate revisions. Pending writes are replayed after a crash only when the destination still matches the expected content; otherwise both versions are retained.

Renames have a separate recovery journal so an interrupted move does not leave duplicate note identities. Late external edits are retained as competing revisions. Closing the window or quitting asks the renderer to flush its current draft before the native process exits.

SQLite FTS5 is a local, rebuildable search index. Revisions and attachment blobs are retained separately. An OS file lock prevents two application processes opening the same local vault.

Selecting another notebook prepares and validates its handle, encryption configuration, index and remembered location before swapping the active handle/key. Failed selection preserves the current notebook and its unlocked key. Reselecting the same canonical folder reuses its handle and scans for external edits. Unavailable remembered folders are not silently recreated. The interface flushes pending text, clears the previous search/filter/history state after a successful switch, and drops cached account state before loading the new notebook's connection status.

## Revision graph

Each immutable revision identifies an item, its parent revisions, path, kind, deletion state, content/blob, attachment dependencies, and creation time. Current heads are revisions not referenced as parents. Device clocks do not select winning content.

Non-overlapping Markdown changes merge from a unique common ancestor. Merge IDs are deterministically derived from item identity and sorted parent IDs, so devices producing the same merge do not generate endless competing merges. Identical heads coalesce. Binary, path, deletion, overlapping-text, and ambiguous-ancestry changes require review. Resolution references every current head.

Tombstones represent deletion without erasing history. Restoration creates another revision. Uploaded identities are persisted before requests. Blobs are uploaded before dependent revisions; revisions are uploaded in parent order. The readable tree is a rebuildable projection of history, never the authoritative source of edits.

## Drive layout

```text
Wattle Notes - Notebook/
  vault.json                    # KDF parameters and wrapped master keys
  Work/
    Meeting.md.enc              # encrypted current Markdown
  attachments/
    diagram.png.enc             # encrypted current attachment
  .sync/
    objects/<revision-id>.enc    # authenticated revision payloads
    blobs/<blob-id>.enc          # chunked authenticated attachment payloads
```

Drive `appProperties` identify the vault, object role, revision/item identity, or blob identity. They contain no note bodies, tags, snippets, or attachment bytes. Drive IDs are generated by Google before upload and recorded locally for idempotent retry. Resumable sessions send encrypted chunks and query acknowledgment after uncertain delivery.

The Drive adapter is behind a `Remote` trait. Changed remote object versions are authenticated again and checked against immutable local snapshots; unchanged mirrors are not reuploaded. Integration tests run complete two-/three-device scenarios against an in-memory transport that records uploads, injects interruptions, and removes objects. Live OAuth/Drive and operating-system credentials are separate acceptance checks.

## Optional WebDAV backup

`backup.rs` builds a versioned encrypted snapshot from current files and a consistent local metadata snapshot. `webdav.rs` handles HTTPS Basic authentication with an OS-stored app password, PROPFIND listings, streamed PUT, and MOVE publication. The endpoint is user-configured; requests never follow redirects. Backups are manual and independent of the Drive revision protocol. Restore validates and stages a complete notebook before publishing a new folder; it retains the original vault identity/history for subsequent reconciliation. The frontend delegates backup through the same pending-editor save flow.

## Live Markdown editing

Read mode uses CodeMirror decorations to display headings, inline formatting, lists, wiki/Markdown links and attachment images while editing the canonical Markdown body. Markers near the caret remain visible for unambiguous editing. The toolbar and shortcuts dispatch normal source transactions and retain CodeMirror undo; the resulting body is passed through the existing frontmatter-preserving draft, autosave and conflict flow. Complex blocks remain literal source rather than undergoing a lossy HTML conversion. Local image widgets use the same bounded attachment reader and object-URL cleanup as split preview; raw HTML and remote image URLs never become active browser resources. Ctrl/Cmd-click opens links, and a plain click edits their labels.
